# 产品共识

## 从哪里起步

主理人观察到，一些精品花店靠自媒体和微信接单，顾客会拿外部截图问能否复刻，也会从朋友圈挑店家做过的款，或给预算让花艺师发挥。盲盒有时可以限定色系或大小。花材供应和节日影响报价，照片与成品之间的落差，是主理人自己在意的问题。这些观察的适用范围有待试点验证。

起步时免费，让花店愿意展示作品，让老客方便挑款，让新客能发现店家。佣金等业务扩大后再考虑，费率、平台收款和交易规则均待讨论。顾客端与花店管理端是两个独立应用。当前优先按独立移动 App 定义顾客端的品牌、导航和选花体验。首发倾向微信小程序，独立客户端的开发与上架时间待定。

## 顾客端的四个入口

| 入口 | 主理人要的体验 |
| --- | --- |
| 逛花 | 默认首页。顾客晒收到的花、分享插瓶和园艺日常，花店展示作品。得物的参考点是内容浏览体验。 |
| 选花束 | 像逛商品一样向下看很多花束款式。按大小、用途筛选，也希望从调色盘选几种颜色组合，再缩小范围。点进喜欢的款，把参考图发给收花地附近的花店，沟通能否做、要改哪里、怎么报价。 |
| 找花店 | 按收花地找当地精品店，位置入口设想在左上角。进店看实拍作品、咨询、了解何时有空接单。花店主页也能发给自己的微信顾客。 |
| 我的 | 顾客个人页，位于最右。已有讨论建议放自己的发布和收藏，具体栏目等设计时确认。 |

## 对设计有影响的决定

- 顾客可以先选款再找店，也可以先找店再看它的作品。参考图本身不能保证当地花材、可交付效果或当前售价。
- 希望不同店上传的花束照片更容易比较。用 AI 统一光线、背景属于待验证的想法。样图要与原图核对花瓣颜色、花量、轮廓和大小感。
- 淘宝是「能连续浏览很多款」的参照。东东电竞启发了服务平台与商家入驻的思路。各页面的视觉和订花步骤仍由芙洛拉自己决定。

## 有意留给后续的问题

1. 首屏的图有多大、能看到多少款、调色盘如何出现和多选。颜色筛选如何处理主花、配花和包装色。
2. 参考款来自哪家店、谁同意展示、顾客能发给哪些店。顾客点选店家还是由平台匹配，发给几家，如何接收回复。
3. 作品参考价、当日报价和可预订档期如何表达。来图定制、店内同款、花艺师盲盒各自怎么沟通。
4. 哪些沟通在芙洛拉内完成，哪些适合转到微信，顾客从哪里找回店家的回复。支付、配送、售后与订单记录都还没有定方案。
5. 首批合作城市、商家数量、上线时间、开发方案和预算均待确认。
